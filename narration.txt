1. 자동화의 목표와 학습 순서

AI와 함께하는 건축 자동화에 오신 것을 환영합니다. 이 교재는 건축사사무소가 실제 업무에 도입할 수 있는 자동화 흐름을 다룹니다. 먼저 결과물을 세 가지로 나누겠습니다. 첫째는 조감도처럼 설계 의도를 전달하는 이미지입니다. 둘째는 길이와 높이를 다시 계산할 수 있는 삼차원 모델입니다. 셋째는 축척, 치수, 단면과 도면 번호가 정합성을 갖춘 설계 도서입니다. 보기 좋은 이미지가 만들어졌다고 해서 정확한 도면이 완성된 것은 아닙니다. 따라서 공통 입력 데이터를 먼저 정하고, 블렌더나 스케치업으로 모델을 생성한 다음, 도면과 시각화로 분기하는 방식으로 학습합니다. 실습은 실제 의뢰인의 자료가 아닌 가상의 사무소 건물을 사용합니다. 대지는 가로 삼십 미터, 세로 이십사 미터이고, 건물은 가로 십팔 미터, 세로 십이 미터, 삼 층, 층고 삼 점 육 미터입니다. 이 수치는 교육을 위한 가정이며 어떤 지역의 법규 적합성을 뜻하지 않습니다. 이 교재의 애니메이션은 자동화의 원리를 설명하는 브라우저 시뮬레이션입니다. 실제 프로그램 화면 녹화와 구분해서 보십시오. 학습을 마치면 요구사항을 구조화하고, 실행 결과를 검사하고, 수정 이력을 남기는 한 바퀴의 작업을 직접 수행하는 것이 목표입니다.

2. 참고 영상 3개를 읽는 방법

참고 영상 세 개의 제목과 게시자를 확인했습니다. 첫 번째는 힉스필드 엠씨피를 연결한 일인 설계사무소 실험, 두 번째는 조닝과 에이아이 렌더 및 견적을 만드는 스킬, 세 번째는 웹과 스케치업을 직접 제어하는 활용법을 주제로 합니다. 다만 이번 조사에서는 전체 자막과 장면을 확보하지 못했습니다. 따라서 영상에서 어떤 기능이 실제로 성공했다거나 몇 배 빨라졌다고 단정하지 않습니다. 화면에 정리한 내용은 제목에서 도출한 학습 질문입니다. 영상을 직접 볼 때는 세 가지를 기록해 보십시오. 첫째, 요청 전에 어떤 파일과 조건을 준비했는지 기록합니다. 둘째, 에이아이가 호출한 도구와 프로그램에서 바뀐 대상을 적습니다. 셋째, 결과가 이미지인지 편집 가능한 모델인지 구분합니다. 실패 장면이나 수작업 보정이 생략되었다면 자동화 범위를 판단하기 어렵습니다. 특히 예쁜 렌더 결과만으로 도면의 치수 정확도를 평가해서는 안 됩니다. 영상에 등장하는 서비스가 내 계정에도 연결되어 있다고 가정하지 마십시오. 이 교재에서는 현재 확인된 도구와 추가 연결이 필요한 프로그램을 분리해 안내합니다. 나중에 영상 파일이나 자막을 확보하면, 타임코드와 주장, 실제 조작과 검증 결과를 한 줄씩 대응시켜 분석을 확장할 수 있습니다. 추가로 공개 설명란과 게시자 목차도 확인했습니다. 첫 영상은 이번 편의 범위를 이미지 생성으로 소개하고 광고 포함을 표시합니다. 두 번째는 조닝과 렌더, 견적의 반복 절차를 강조합니다. 세 번째는 웹 제어와 프로그램 제어, 도면과 삼차원 공간 연결을 나누어 설명합니다. 스케치업 영상의 제작 노트에는 제작자가 직접 기획하고 모델링했다고 적혀 있습니다. 따라서 전 과정이 무인으로 자동화됐다고 해석하지 않습니다.

3. 내 계정의 도구 지도를 먼저 그리기

계정에 연결된 프로그램 활용은 도구 목록에서 출발합니다. 엠씨피는 에이아이가 외부 프로그램의 기능을 정해진 입력으로 호출하는 규약입니다. 플러그인은 이런 연결이나 사용 지침을 묶어서 제공하는 패키지이고, 스킬은 작업 순서와 품질 기준을 반복해서 적용하는 지침입니다. 세 개가 항상 같은 뜻은 아닙니다. 예를 들어 스킬에 블렌더 작업 절차가 적혀 있어도 블렌더 제어 도구가 연결되지 않았다면 직접 조작할 수 없습니다. 이번 환경에서는 깃허브 인증과 헤이젠 음성 생성을 실제로 확인했습니다. 캔바, 피그마, 캡컷, 런웨이, 구글 드라이브의 도구도 제공되지만, 모든 계정 기능과 사용권까지 검증했다는 뜻은 아닙니다. 블렌더는 컴퓨터에 설치되어 있으므로 파이썬 스크립트 실행 방식으로 실습합니다. 스케치업 전용 엠씨피는 목록에 없으므로 루비 예제를 제공하고 사용자가 데스크톱 프로그램에서 실행하는 경로를 설명합니다. 업무 도입 시에도 이 구분을 표로 관리하십시오. 목록 확인, 읽기 성공, 쓰기 성공, 결과 검수까지 단계별로 표시하면 어디에서 문제가 생겼는지 찾기 쉽습니다. 처음에는 파일 읽기나 음성 목록 조회처럼 범위가 작은 작업부터 시작합니다. 그 다음 가상 데이터를 생성하고 결과가 예상과 일치할 때 실제 프로젝트로 확장합니다.

4. 자연어 요구사항을 설계 데이터로 바꾸기

자연어를 곧바로 모델로 바꾸면 빠르지만, 잘못 해석된 조건이 어디에서 생겼는지 찾기 어렵습니다. 먼저 설계 조건을 작은 데이터 파일로 바꾸겠습니다. 대지와 건물 크기, 층수와 층고를 분리하고 각 숫자에 단위를 붙입니다. 실습에서는 미터를 사용합니다. 원점은 대지의 중심, 북쪽은 와이축의 양의 방향입니다. 이 기준을 모델링 프로그램과 도면에서 공유해야 배치 방향이 뒤집히지 않습니다. 층수는 정수인지, 길이는 양수인지, 건물이 대지보다 크지 않은지 검사합니다. 이 검사는 기하학적 조건일 뿐 법적 적합성 검사가 아닙니다. 건폐율, 용적률, 이격거리처럼 프로젝트에 적용할 기준은 소재지와 용도, 기준일을 확인한 별도의 검토가 필요합니다. 모르는 값은 빈칸이나 널로 남겨 두고 질문 목록으로 보냅니다. 에이아이가 그럴듯한 숫자를 만들어 넣게 하지 않습니다. 실습 기준으로 건물 바닥면적은 이백십육 제곱미터이고 세 개 층을 단순 합산하면 육백사십팔 제곱미터입니다. 높이는 십 점 팔 미터입니다. 이 세 숫자는 이후 프로그램 출력과 대조할 기준이 됩니다. 값이 다르면 단위, 스케일 적용, 처마나 슬래브의 포함 범위부터 확인하십시오. 입력 파일에 수정 번호를 남기면 조감도와 도면이 어떤 조건에서 생성됐는지도 추적할 수 있습니다.

5. Blender를 MCP로 연결하는 구조

블렌더를 엠씨피로 직접 제어하려면 두 부분이 함께 필요합니다. 하나는 블렌더 안에서 요청을 받는 애드온이고, 다른 하나는 에이아이 클라이언트와 통신하는 엠씨피 서버입니다. 애드온만 설치하거나 서버만 등록하면 연결이 완성되지 않습니다. 이 교재에서 소개하는 엠씨피 포 블렌더는 커뮤니티 프로젝트이며 블렌더의 공식 기능으로 단정해서는 안 됩니다. 설치 전에는 원본 저장소와 사용 중인 버전의 문서를 확인합니다. 설치가 끝나면 실제 설계 파일 대신 빈 실습 파일을 엽니다. 먼저 현재 장면의 단위와 객체 이름을 조회해 달라고 요청합니다. 조회가 성공하면 전용 컬렉션에 일 미터 큐브 하나를 생성하고 크기를 읽어 오도록 합니다. 이 작은 왕복 검증을 통해 연결, 실행, 결과 확인이 모두 되는지 알 수 있습니다. 연결 실패 시에는 서버 실행 여부, 애드온의 시작 상태, 호스트와 포트 일치, 실행 파일 경로를 순서대로 확인합니다. 같은 포트를 사용하는 중복 실행도 점검합니다. 임의 코드 실행이 가능한 도구이므로 연결을 외부 인터넷에 노출하지 않고, 프로젝트 복사본과 제한된 출력 폴더를 사용합니다. 현재 세션에는 블렌더 엠씨피 도구가 없어서 다음 실습은 로컬 파이썬 실행으로 제공합니다. 엠씨피가 연결된 뒤에도 동일한 입력과 검수 기준을 적용할 수 있습니다.

6. Blender 실습: 조건 → 모델 → 조감도

이 실습은 조건 파일을 읽어 개념 모델과 조감도를 만드는 가장 작은 자동화입니다. 교재 폴더 안의 이그잼플스 폴더에는 입력 제이슨과 블렌더 파이썬 파일이 들어 있습니다. 블렌더의 스크립팅 작업 공간에서 파일을 열고 실행합니다. 스크립트는 교육용 장면을 새로 만들고 미터 단위를 설정합니다. 대지, 층별 슬래브, 건물 매스, 입면 분할을 각각 이름이 있는 객체로 생성합니다. 이렇게 이름을 붙여야 다음 요청에서 특정 층만 수정하거나 수량을 집계할 수 있습니다. 카메라는 건물의 대각선 위에 놓고 중심을 향하게 합니다. 같은 설계안을 비교하려면 카메라, 해상도, 빛의 조건을 고정하는 것이 좋습니다. 실행 후에는 모델 파일, 조감도, 상부 투영과 검증 보고서를 함께 엽니다. 보고서의 바닥면적 이백십육, 층별 면적 합 육백사십팔, 높이 십 점 팔이 기준과 일치하는지 확인하십시오. 화면의 슬래브는 개념 표현을 위해 매스보다 조금 넓게 만들었으므로 보고서의 바닥면적은 입력한 본체 기준입니다. 법정 면적을 자동 계산한 결과가 아닙니다. 다음 과제는 입력의 층수를 사 층으로 바꾸는 것입니다. 높이가 십사 점 사 미터, 면적 합이 팔백육십사 제곱미터로 바뀌어야 합니다. 기존 출력 파일은 같은 이름으로 갱신되므로 비교본을 먼저 보관하십시오. 한 변수씩 바꾸고 결과를 검사하면 생성 속도보다 재현성을 먼저 확보할 수 있습니다.

7. 조감도에서 도면으로 넘어갈 때

조감도가 완성되면 곧바로 도면을 만들 수 있을 것 같지만, 중간에 중요한 단계가 있습니다. 상부 투영은 위에서 내려다본 모습이고 평면도는 정해진 높이에서 건물을 잘라 본 표현입니다. 지붕이 그대로 있는 모델을 위에서 렌더하면 지붕 배치만 보입니다. 내부 벽과 개구부가 없는 매스에서 상세 평면도를 얻을 수는 없습니다. 따라서 도면 자동화를 시작하기 전에 벽 두께, 문과 창의 위치, 층 레벨과 공간 구획을 모델에 넣어야 합니다. 도면마다 절단 높이와 방향, 표시 범위도 지정합니다. 정투영 카메라는 원근 왜곡을 없애지만 이것만으로 축척이 보장되지는 않습니다. 이미지 픽셀과 종이 크기를 연결하고 출력 배율을 확인해야 합니다. 예를 들어 실제 십 미터 길이는 백 분의 일 축척에서 종이 위 백 밀리미터입니다. 프린터가 페이지에 맞추기를 켜면 이 크기가 바뀔 수 있습니다. 부재의 의미와 수량을 함께 다루려면 본사이와 아이에프씨 같은 빔 경로를 검토합니다. 메시 덩어리를 파일 형식만 바꾸어 저장하는 것과 벽, 슬래브, 공간으로 분류하는 것은 다릅니다. 도면 산출 이후에는 평면의 문 위치가 입면과 일치하는지, 단면 레벨이 층고와 일치하는지 비교합니다. 에이아이는 초안을 만들고 반복 검사를 도울 수 있지만, 실제 설계 도서의 전문 검토는 별도 단계로 유지합니다.

8. SketchUp 실습: Ruby로 반복 모델 만들기

스케치업은 루비 에이피아이로 반복 모델링을 자동화할 수 있습니다. 현재 전용 엠씨피 연결은 확인되지 않았으므로 이 교재에서는 작성된 코드를 사용자가 데스크톱 루비 콘솔에서 실행하는 방식을 사용합니다. 처음에는 빈 모델을 열고 파일을 저장합니다. 예제를 불러오면 교육용 그룹 안에 층별 매스가 만들어집니다. 그룹을 쓰는 이유는 주변 면과 선이 의도치 않게 붙는 일을 줄이고 수정 대상을 분명하게 하기 위해서입니다. 스케치업 루비에서는 길이에 미터 변환을 명시하는 것이 중요합니다. 십팔이라는 숫자와 십팔 미터는 같은 의미가 아닐 수 있습니다. 예제에서는 점 좌표와 돌출 높이에 점 엠을 붙여 변환합니다. 면의 법선이 아래를 향하면 먼저 뒤집고 양의 높이로 돌출합니다. 그래야 생성 방향을 예측하기 쉽습니다. 작업 시작과 완료를 하나의 오퍼레이션으로 묶으면 오류가 생겼을 때 취소하거나 실행 취소 한 번으로 되돌릴 수 있습니다. 전체 예제는 같은 이름의 교육용 그룹이 이미 있으면 중복 생성을 막습니다. 반복 실행 전에 기존 실습 그룹을 확인하고 별도 복사본에서 작업하십시오. 실행 후에는 눈으로만 판단하지 말고 줄자 도구로 너비와 깊이, 높이를 측정합니다. 이 예제는 층별 덩어리 생성 단계입니다. 실내 평면과 구조, 창호 상세는 후속 모델링 작업이 필요하며 스크립트가 자동으로 완성하지 않습니다.

9. SketchUp 장면과 LayOut을 납품 도면으로 연결

스케치업에서 반복 생성이 가능해지면 다음 목표는 도면 뷰의 재사용입니다. 모델의 층과 벽, 창호를 그룹이나 컴포넌트로 나누고 표시 제어는 태그로 관리합니다. 태그는 화면에 무엇을 보일지 결정하는 도구이지 형상의 의미를 자동으로 정의하는 기능은 아닙니다. 조감도, 정면, 측면과 층별 평면을 장면으로 저장합니다. 도면용 뷰에서는 원근을 끄고 평행 투영과 방향 정렬을 확인합니다. 평면이나 단면은 단면 평면의 위치와 활성 상태를 관리해야 합니다. 같은 모델이라도 단면 높이가 다르면 문과 창이 보이는 방식이 달라집니다. 레이아웃을 사용할 수 있는 상품 구성이라면 이 장면을 문서에 배치하고 축척과 도면 제목을 지정합니다. 중요한 것은 모델을 수정한 다음입니다. 참조 모델만 갱신했다고 모든 문서가 올바르게 바뀌었다고 생각하지 마십시오. 뷰의 표시 상태, 연결된 치수, 수동으로 작성한 주석을 다시 검사합니다. 수동 텍스트로 적은 높이가 모델 변경을 따라가지 않을 수 있습니다. 출력한 피디에프에서는 선 굵기와 글자 크기를 실제 종이 크기로 확인하고, 도면 번호와 개정 번호를 점검합니다. 실습에서는 삼 층을 사 층으로 바꾼 뒤 입면 높이와 단면 레벨, 면적표가 함께 바뀌었는지 체크리스트로 확인하십시오. 이것이 단순 생성보다 중요한 변경 자동화입니다.

10. 재사용 가능한 건축 자동화 지시문

좋은 프롬프트는 긴 수식어보다 명확한 계약을 담습니다. 목표, 입력, 수정 범위, 절차, 산출물, 검수와 실패 처리를 순서대로 적습니다. 예를 들어 멋진 삼 층 건물을 만들어 달라는 요청에는 층고와 단위, 지붕과 본체의 경계, 어떤 파일을 수정해도 되는지가 없습니다. 반면 공통 입력 파일만 사용하고 교육용 장면만 수정하라고 지정하면 작업 경계를 확인하기 쉽습니다. 결과 보고에는 이미지 한 장뿐 아니라 실제 치수와 객체 수, 저장 경로와 오류 여부를 포함시킵니다. 에이아이가 코드를 작성했다는 사실과 프로그램이 실행에 성공했다는 사실도 나누어 기록합니다. 이 절차가 몇 차례 안정적으로 반복되면 작업 지침으로 묶을 수 있습니다. 스킬에는 적용 상황과 입력 형식, 단계별 검사, 실패 시 중단 조건을 담습니다. 한 번의 예외적 성공을 만능 자동화로 포장하지 마십시오. 버전이 바뀌면 에이피아이 이름이나 출력 방식이 바뀔 수 있으므로 검증한 프로그램 버전도 적어 둡니다. 실습에서는 폭, 깊이, 높이의 허용 오차를 일 밀리미터로 설정할 수 있지만, 이것은 교육용 검사 기준입니다. 실제 프로젝트의 허용 오차와 품질 기준은 사무소가 별도로 정합니다. 가장 유용한 스킬은 원하는 결과뿐 아니라 잘못된 결과를 알아보는 방법까지 함께 저장하는 스킬입니다.

피그마는 건축 모델의 기하학을 검증하는 도구보다 설계 의도를 전달하는 설명 보드에 잘 맞습니다. 먼저 블렌더나 스케치업에서 검토한 조감도와 도면 이미지를 준비합니다. 그 다음 입력 조건, 매스 형성, 동선, 검토 쟁점 순서로 프레임을 배치합니다. 현재 연결 도구에는 파일을 만들고 읽고 수정하는 기능이 있으므로 자연어 요청을 여러 단계로 나눌 수 있습니다. 첫 단계는 대상 파일과 페이지를 확인하는 것입니다. 두 번째는 이미지와 설명을 배치하는 것이고 세 번째는 결과를 렌더해 읽기 쉬운지 검사하는 것입니다. 기존 실무 파일 전체를 바꾸기보다 복사본이나 지정 프레임을 대상으로 시작하십시오. 설명 텍스트와 화살표, 범례를 편집 가능한 객체로 유지하면 건축주 피드백에 맞추어 수정하기 쉽습니다. 도면 이미지에서 치수를 새로 추정하게 하지 말고 검증된 모델 수치만 가져옵니다. 보드 한쪽에는 원본 모델의 개정 번호와 작성 기준일을 적습니다. 동적 설명이 필요하면 매스가 올라가고 동선이 나타나는 순서를 타임라인으로 구성할 수 있습니다. 그러나 이런 애니메이션은 표현을 위한 것이며 실제 모델링 프로그램 조작의 증거는 아닙니다. 이 교재에서도 원리 시뮬레이션과 실제 프로그램에서 생성한 결과를 구분하여 표시합니다.

13. CapCut·Runway: 설명 영상과 컨셉 영상 분리

이번 제작에서는 먼저 연결된 헤이젠 도구로 한국어 음성 목록을 조회하고 해설 파일 생성을 실제로 확인했습니다. 여러 단원을 만들던 중 무료 음성 잔여량 제한이 발생했습니다. 추가 결제는 하지 않고 컴퓨터에 설치된 마이크로소프트 혜미 한국어 음성으로 전체 해설을 다시 구성했습니다. 따라서 하단의 연속 재생기는 같은 로컬 목소리로 모든 단원을 읽고, 본문에는 헤이젠으로 생성한 실제 샘플을 별도로 제공합니다. 이것은 연결 도구가 제한에 걸렸을 때 작업을 완성하는 대체 경로의 사례입니다. 음성 원고는 목적과 조작 순서, 검사 방법과 오류 복구를 함께 설명합니다. 숫자와 단위는 읽기 쉽게 풀어 쓰고, 긴 원고를 문단으로 나누어 각각 음성 파일을 만듭니다. 문단별 파일의 실제 길이를 계산해 한 단원으로 합치면 정확한 문단 시작 시간을 기록할 수 있습니다. 재생기는 이 구간표와 현재 음성 시간을 비교해 해당 문단으로 화면을 이동합니다. 다음 단원은 현재 파일이 끝났을 때 자동으로 재생합니다. 오 초마다 핵심 키워드에 빨간 밑줄을 옮기는 기능도 실제 음성 시간을 기준으로 작동합니다. 이것은 한 단어씩 정확히 맞춘 자막이 아니라 학습의 초점을 주기적으로 알려 주는 강조입니다. 배속 변경과 일시정지, 탐색에도 같은 시간 기준을 사용합니다. 자동 스크롤이 불편하면 재생기에서 끌 수 있습니다. 원고를 수정할 때는 음성 파일과 구간표를 함께 다시 만들어야 화면과 소리가 어긋나지 않습니다.

15. Google Drive: 요구사항·면적표·회의록을 잇기

건축 자동화가 사무소 업무로 이어지려면 모델 밖의 문서도 연결해야 합니다. 구글 드라이브에서는 요구사항, 면적표와 회의록을 공통 프로젝트 번호로 관리하는 방식이 유용합니다. 먼저 지정한 폴더에서 파일을 찾고 제목과 수정일을 확인합니다. 비슷한 이름의 이전 문서를 최신 요구사항으로 읽는 실수를 막기 위해서입니다. 문서에서 확정된 조건과 가정, 미결 질문을 나눈 다음 모델 입력 초안을 만듭니다. 서로 충돌하는 치수가 나오면 하나를 임의로 선택하지 말고 질문 목록에 올립니다. 면적표에는 계산값뿐 아니라 단위, 계산식과 원본 모델의 개정 번호를 적습니다. 스프레드시트를 수정할 때는 탭 이름과 셀 범위를 지정하고 기존 수식을 보존하도록 요청합니다. 표를 보기 좋게 정리하는 과정에서 수식을 값으로 덮어쓰지 않는지 확인해야 합니다. 견적은 면적에 숫자 하나를 곱하는 것으로 완성되지 않습니다. 단가의 기준일, 포함 공종과 제외 항목, 현장 조건을 함께 기록합니다. 에이아이가 제시한 근거 없는 단가는 미확인으로 남깁니다. 회의록에는 결정 사항과 담당자, 기한, 관련 모델 번호를 적어 다음 수정 요청과 연결합니다. 이 교재에서는 개인 드라이브 자료를 읽지 않았고 가상의 조건만 사용했습니다. 실제 협업에서는 허용된 프로젝트 폴더와 공개 범위를 명시한 뒤 문서 자동화를 적용하십시오.

16. 자동화 결과를 승인 가능한 상태로 만들기

자동화 결과의 승인은 성공이라는 메시지를 읽는 것으로 끝나지 않습니다. 먼저 입력 파일의 단위와 좌표, 개정 번호를 확인합니다. 그 다음 실제 모델의 폭과 깊이, 높이를 읽어 기준값과 비교합니다. 층수와 객체 수, 그룹 이름도 검사하면 중복 실행이나 누락을 찾을 수 있습니다. 조감도 검수에서는 원본 모델의 창과 층수, 입면 비례가 유지되는지 봅니다. 생성 이미지는 존재하지 않는 문이나 창을 그럴듯하게 추가할 수 있습니다. 도면 검수에서는 평면과 입면, 단면 사이의 정합성을 확인합니다. 한 도면만 정확해도 다른 도면이 이전 버전이면 납품 묶음은 일관되지 않습니다. 파일을 실제로 열어 보고 음성과 링크, 외부 참조가 동작하는지도 검사합니다. 검사 결과는 통과, 실패, 미확인으로 나눕니다. 확인하지 못한 항목을 통과로 표시하지 않는 것이 중요합니다. 효과 측정도 같은 원칙입니다. 자동화의 실행 시간만 재고 준비와 검토, 재작업 시간을 빼면 실제 절감 효과를 과장하게 됩니다. 기존 방식과 자동화 방식에서 같은 범위의 총 시간을 기록하십시오. 실패가 나면 입력, 실행, 출력, 검수 중 어느 단계인지 표시하고 그 단계부터 복구합니다. 실무에서는 건축사의 판단과 분야별 전문 검토가 필요한 결정을 별도로 승인받고, 에이아이의 생성 결과와 사람의 판단 기록을 함께 남깁니다.

17. GitHub: 교육 자료를 버전과 함께 공개하기

완성된 교재는 깃허브 저장소에 원고와 예제, 음성 파일을 함께 보관하면 수정 이력을 관리하기 쉽습니다. 깃허브 페이지스는 정적 에이치티엠엘과 이미지, 자바스크립트 같은 파일을 웹사이트로 제공하는 방식입니다. 공개 전에 고객 자료와 비밀 키, 개인 문서가 포함되지 않았는지 확인합니다. 이 교재는 가상의 프로젝트를 사용합니다. 사이트 내부의 파일 경로는 상대 경로로 작성하면 저장소 이름이 붙은 주소에서도 이미지와 음성이 연결됩니다. 파일을 업로드한 뒤에는 페이지스의 게시 원본을 설정하고 배포가 끝났는지 확인합니다. 예상 주소만 알려 주는 대신 실제 주소에서 본문과 음성을 열어 보는 것이 검증입니다. 정적 교재와 프로그램 제어도 구분해야 합니다. 웹페이지를 방문한다고 방문자의 엠씨피 계정에 연결되거나 블렌더가 자동 실행되는 것은 아닙니다. 웹사이트는 설명과 예제를 제공하고, 실제 도구 실행은 각자의 권한이 있는 작업 환경에서 수행합니다. 이후 교재를 수정할 때는 글만 바꾸지 말고 해당 음성과 시간 정보, 예제의 입력값도 함께 갱신합니다. 최종 과제는 가상 설계안 하나로 요구사항부터 모델, 조감도와 설명 자료, 음성 및 검토 기록까지 완주하는 것입니다. 다른 사람이 같은 입력으로 재현할 수 있다면 자동화가 개인의 요령을 넘어 사무소의 자산으로 바뀌기 시작한 것입니다.
